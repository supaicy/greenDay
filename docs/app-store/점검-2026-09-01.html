그래서앱스토어에는 라이트가 낫습니다 — Apple의 밝은 크롬 위에 놓이고 네이티브로 보입니다. 사이트에는 그대로 못 씁니다 — 테두리를 굵히거나 그림자를 주거나, 다크를 유지해야 합니다. 아래 나란히 보시면 바로 보입니다.

개인정보처리방침이 두 벌입니다

supaicy.github.io/greenDay/privacy.html 과 begreen.dev/privacy·/ko/privacy 가 따로 존재하고 둘 다 200입니다.

그래서환불 기간이 7일/14일로 갈렸던 것과 같은 실패 방식입니다. 앱스토어에 제출하는 URL은 begreen.dev 쪽을 권합니다 — 실제 도메인이고, 두 언어이고, 결제 사이트의 법적 문서와 같은 손에서 관리됩니다. GitHub Pages 사본은 리다이렉트하거나 지우는 게 낫습니다.

왼쪽은 덩어리로 읽힙니다. 오른쪽은 사이드바 색과 테두리만 겨우 남고 본문이 페이지에 녹습니다. 앱스토어에서는 반대로 라이트가 유리합니다 — Apple의 밝은 화면 위에 놓이니까요.

확인한 것 코드로

App Privacy 답안 "수집하지 않음"이 앱스토어 빌드에서는 정확합니다스토어 빌드는 enforcesLicense: false라 라이선스 서버를 부르지 않고, canSelfUpdate: false라 GitHub 업데이트 확인도 안 합니다. 캘린더 동기화는 사용자가 켤 때만이고 기기에서 Apple/Google로 직접 갑니다. 웹 판매본은 다릅니다(라이선스 재검증·업데이트 확인 두 연결) — 그건 Apple이 심사하는 대상이 아닙니다.

정하실 것 셋

  • 번들 ID를 com.supaicy.haru 로 둘지앱 레코드를 만드는 순간 영구히 못 바꿉니다. 지금은 공짜입니다. 동작에는 문제없고, 영원히 옛 이름이 남는 것을 감수할지의 문제입니다.
  • 개인정보처리방침 URL을 어느 쪽으로 제출할지begreen.dev 쪽을 권합니다. 그리고 GitHub Pages 사본은 리다이렉트하거나 지우는 게 낫습니다 — 두 벌은 반드시 갈라집니다.
  • 사이트 스크린샷을 라이트로 바꿀지바꾸시려면 테두리를 굵히거나 그림자를 줘야 합니다. 지금 1px로는 명도차 9라 사라집니다. 아니면 앱스토어만 라이트, 사이트는 다크로 두는 것도 방법입니다.

사이트는 바꾸지 않았습니다. 라이트 이미지를 assets/ 에 넣어만 두고 페이지는 그대로 다크를 가리킵니다 — 위 명도 문제 때문에 바로 교체하는 것이 옳지 않습니다.

캡처 도구는 남겨 뒀습니다. 데이터·화면·테마·크기를 바꿔 다시 찍는 것은 언제든 몇 분입니다.
