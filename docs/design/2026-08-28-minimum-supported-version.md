# 최소 지원 버전 — enforcement 플래그를 이미 설치된 앱에 도달시키는 법

- **상태: 제안. 승인 전까지 코드를 넣지 않는다.**
- 근거: 감사 H17 (`SUMMARY.md`), `src/main/licensing/service.ts:33`
- 작성: 2026-08-28 (감사 후속 웨이브 1, wt-licensing)

## 문제

`IS_ENFORCED`는 **빌드에 박힌 상수**다. 그리고 직판 빌드의 업데이터는
`autoDownload = false`(`src/main/index.ts:163`)라, 사용자가 알림을 보고 직접
"다운로드"를 누르지 않으면 새 빌드가 오지 않는다.

두 사실을 겹치면: **오늘 출하하는 빌드는 영원히 무료다.** 서버를 배포해도,
새 버전에서 플래그를 켜도, 그 설치들은 자기 안에 박힌 `false`를 계속 읽는다.
유료 전환은 "플래그 하나 + 서버 배포"가 아니라 "플래그 하나 + 서버 배포 +
**모든 사용자가 업데이트를 눌러 주기**"가 된다.

지금은 아무도 다치지 않는다 — enforcement가 꺼져 있고 아무것도 안 잠그기
때문이다. 다치는 것은 켜는 날이고, 그때 이 결정을 내리려면 이미 나가 있는
설치들이 벽이 된다. **그래서 켜기 전이 아니라 출하하기 전에 정해야 한다.**

## 먼저 정해야 하는 것 (제품 결정)

이건 기술 문제이기 전에 약속의 문제다. 코드는 어느 쪽이든 쓸 수 있다.

> **오늘 무료로 받은 사람은 계속 무료인가?**

- **예 (grandfather).** 지금 설치한 사람은 영구 무료. 유료화는 새 설치에만.
  — 정직하고, 초기 사용자에게 보상이 되고, 아무 강제 장치도 필요 없다.
  — 대신 "무료 버전을 계속 쓰겠다"는 사람이 남고, 그 사람들에게 버그 수정을
    계속 배달해야 한다(보안 수정은 어차피 배달해야 한다).
- **아니오.** 유예 기간을 주고 전원을 유료 상태 기계로 옮긴다.
  — 그러려면 아래의 최소 지원 버전 체계가 **필수**다. 그것 없이는 옮길 방법이
    자체가 없다.

**추천: 예(grandfather).** 이유 셋.

1. 지금 설치 수가 작다. 강제 장치를 만드는 비용이 그 수보다 크다.
2. 강제 업데이트는 "앱이 스스로를 잠근다"는 새 실패 모드를 만든다. 서버가
   한 번 잘못 답하면 전원이 잠기고, 그건 이 저장소가 라이선스 클라이언트
   전체에서 피하려고 애쓴 바로 그 결과다(`licenseClient.ts` 첫 주석).
3. 그렇게 정해도 아래 체계는 **여전히 필요하다** — 다만 "잠그기 위해"가 아니라
   "취소를 전파하고 깨진 빌드를 회수하기 위해"로 쓰인다. 그쪽이 훨씬 방어하기 쉽다.

이 문서의 나머지는 어느 쪽을 고르든 필요한 배관을 설계한다.

## 설계

### 1. 서버가 최소 버전을 말한다

앱은 이미 30일마다 `/v1/validate`를 친다. 새 채널을 만들지 않고 **그 응답에
얹는다** — 새 엔드포인트는 새 실패 모드이고, 이 응답은 이미 앱이 신뢰하는
경로다.

```
POST /v1/validate  →  { token, expiresAt, policy: { minVersion, enforcedAt } }
```

- `minVersion`: 이 버전보다 낮으면 "지원 종료"를 **안내**한다(잠그지 않는다).
- `enforcedAt`: 유료 판정을 켜는 시각(unix 초). 없으면 켜지 않는다.

**두 값 모두 토큰 안에 서명해 넣는다.** 봉투에만 실으면 hosts 한 줄로 무력화되고,
그러면 이 체계는 정직한 사용자에게만 작동하는 장치가 된다 — 그건 사용자를
불편하게 하는 값만 치르고 아무것도 못 막는 최악의 조합이다.

토큰 페이로드에 두 필드를 더한다(`activationToken.ts`의 `TokenPayload`):

```ts
/** 이 정책이 적용되는 최소 앱 버전. 없으면 정책 없음. */
minVer?: string
/** 유료 판정을 켜는 시각(unix 초). 없으면 켜지 않는다. */
enfAt?: number
```

기존 토큰에는 없는 필드이므로 **둘 다 선택적**이어야 한다. `prod`가 없는 옛
토큰을 `wrongProduct`로 떨어뜨린 것과 같은 이유로, 없는 것은 "정책 없음"이지
`malformed`가 아니다.

### 2. 트라이얼 사용자에게는 토큰이 없다

여기가 어려운 자리다. `enfAt`을 토큰에 실으면 **키가 있는 사람에게만** 도달한다.
정작 옮겨야 하는 대상은 키가 없는 사람이다.

세 가지 답이 있고, 셋의 성질이 다르다.

| 방법 | 도달 범위 | 위조 저항 | 비용 |
|---|---|---|---|
| a. 서명된 정책 문서를 주기적으로 받아 온다 | 전원 | 있음(같은 ed25519 키) | 새 엔드포인트 + 새 폴 |
| b. 업데이트 채널(`latest-mac.yml`)에 얹는다 | 업데이트를 받는 사람 | electron-updater의 서명 | 낮음 |
| c. 빌드에 박고, 새 빌드를 받게 만든다 | 업데이트를 받는 사람 | 코드 서명 | 0 (지금 방식) |

**추천: (a), 단 grandfather를 고른 경우에는 만들지 않는다.**

(a)를 만든다면 `/v1/policy`가 `{ payload, sig }`를 주고, 페이로드는 활성화
토큰과 **같은 키로 서명**한다. 검증은 `activationToken.ts`의 경로를 그대로 쓴다 —
디코드한 원바이트 위에서 검증하고, 재직렬화하지 않는다. 클라이언트는 마지막으로
본 정책을 `license.json`에 두고, `enfAt`은 **올리기만 하는 래칫**으로 다룬다
(`lastSeenMs`와 같은 성질). 그래야 오프라인으로 되돌릴 수 없다.

### 3. "지원 종료"는 잠그는 것이 아니다

`minVersion`에 미달하면 **안내만** 한다. 배너 한 줄 + 업데이트 버튼.

잠그지 않는 이유: 잠그는 순간 이 체계가 "서버가 한 줄 잘못 답하면 전원이 앱을
못 쓰는" 장치가 된다. 그 위험은 우리가 얻는 것보다 크다. 그리고 어차피
**유료 판정 자체가 서버 없이 로컬에서 돌아가므로**(이 모듈의 설계 전체가 그렇다),
버전으로 잠글 이유가 없다.

예외 하나: **보안 수정을 강제해야 하는 경우.** 그때는 `minVersion`이 아니라
별도의 `revokeBelow`를 쓰고, 그 판단은 사람이 한 번씩 내린다.

### 4. autoDownload를 켠다

`index.ts:163`의 `autoDownload = false`가 이 문제의 절반이다. 자동 다운로드 +
`autoInstallOnAppQuit`(이미 켜져 있다)이면, 앱을 한 번 껐다 켜는 것만으로
새 빌드가 들어간다. 데스크톱 앱은 몇 주씩 안 꺼지지만 결국은 꺼진다.

> **주의: `src/main/index.ts`는 wt-shell 소유다.** 이 한 줄은 그쪽에서 바꿔야 한다.

## 그래서 지금 무엇을 하는가

**아무 코드도 넣지 않는다.** 위의 제품 결정이 먼저다.

- **grandfather로 간다면**: (4)만 하고 나머지는 버린다. 유료화는 새 설치에만
  적용되고, `IS_ENFORCED`는 다음 메이저에서 켠다.
- **전원을 옮긴다면**: (1)(2a)(3)(4)를 **enforcement를 켜기 전에, 그리고 지금
  출하하는 빌드 안에** 넣어야 한다. 나중에 넣으면 그때 나가 있는 설치들이 다시
  같은 벽이 된다.
