1단계 — 프로비저닝 프로파일 받기

App Store 빌드는 앱 안에 이 앱 전용 프로파일을 심어야 합니다. 다른 앱 것이면 빌드는 멀쩡히 끝나고 업로드 단계에서 거절됩니다 — 그래서 프리플라이트가 미리 막습니다.

1

App ID가 등록돼 있는지 확인

developer.apple.com → 로그인 → Certificates, Identifiers & Profiles → Identifiers

목록에서 com.begreen.greenday를 찾습니다.

  • 있으면 2로 넘어갑니다.
  • 없으면 + → App IDs → App → Platform macOS → Bundle ID는 Explicit을 고르고 com.begreen.greenday를 그대로 입력 → Description은 Greenday → Capabilities는 기본값 그대로 두면 됩니다(이 앱이 쓰는 샌드박스 권한은 별도 등록이 필요 없습니다) → Continue → Register.
철자가 정확해야 합니다. com.begreen.greenday — 2026-09-07에 com.supaicy.haru에서 바꾼 값입니다. 옛 ID로 발급하면 프리플라이트가 "다른 앱의 것"이라고 잡아냅니다.
2

프로파일 만들기

같은 화면 왼쪽 → Profiles → +

  1. 종류는 Distribution 묶음 아래의 Mac App Store Connect를 고릅니다. (Apple이 이름을 종종 바꿉니다 — Mac App Store로 보일 수도 있습니다. macOS · 배포용이면 맞습니다. Developer ID나 Mac Development는 아닙니다.)
  2. App ID로 com.begreen.greenday를 고릅니다.
  3. 인증서로 Apple Distribution: MINSEOK SHIN을 고릅니다. (이미 이 맥에 있는 그것입니다.)
  4. 이름은 자유 — 예: Greenday Mac App Store.
  5. Generate → Download.
3

받은 파일을 정해진 자리에 두기

내려받은 파일은 보통 ~/Downloads/Greenday_Mac_App_Store.provisionprofile 같은 이름입니다. 아래를 터미널에 그대로 붙여 넣으면 이름까지 맞춰 옮깁니다.

cd ~/Code/services/greenDay
cp ~/Downloads/*.provisionprofile resources/embedded.provisionprofile
npm run mas:preflight

프리플라이트의 2/6 프로비저닝 프로파일이 이렇게 나오면 성공입니다:

  ✓ 프로파일 App ID 일치: 32R6RHXU36.com.begreen.greenday
  ✓ 플랫폼: macOS
  ✓ 팀: 32R6RHXU36
  ✓ 만료: 2027-…

✗ 프로파일이 다른 앱의 것입니다가 나오면 1단계의 App ID를 잘못 고른 것이니 다시 발급하면 됩니다.

2단계 — Google OAuth 클라이언트 ID 받기

Google 캘린더 연동에만 쓰이는 값이고 비밀이 아닙니다(공개 클라이언트 + PKCE). 다만 빌드 시점에 앱에 박히기 때문에, 없이 나간 릴리스는 연동이 통째로 죽습니다 — 그래서 릴리스 빌드가 값이 비면 실패하도록 돼 있습니다.

1

Google Cloud 콘솔에서 만들기

console.cloud.google.com → 프로젝트 선택(또는 생성)

  1. API 및 서비스 → 라이브러리 → Google Calendar API → 사용 설정.
  2. OAuth 동의 화면 → 사용자 유형 외부. 앱 이름 Greenday, 지원 이메일, 개인정보처리방침 https://begreen.dev/privacy. 범위 추가에서 .../auth/calendar.app.created 하나만 넣습니다.
  3. 게시 상태가 테스트인 동안은 테스트 사용자에 등록된 계정만 로그인됩니다 — 본인 계정을 넣어 두세요.
  4. 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID → 애플리케이션 유형 데스크톱 앱.
  5. 만들어진 클라이언트 ID를 복사합니다 — …​.apps.googleusercontent.com으로 끝나는 문자열입니다.
유형은 반드시 "데스크톱 앱"입니다. 번들 ID를 묻는 iOS 유형이 아닙니다. 이 앱은 루프백(127.0.0.1) 리디렉션 + PKCE를 쓰고, 데스크톱 앱 유형은 루프백을 자동 허용해서 리디렉션 URI를 따로 등록할 것이 없습니다. 클라이언트 보안 비밀은 쓰지 않습니다 — 코드가 보내지 않습니다.

제게 전달하는 방법

무엇어떻게 주시면 되는지비밀인가
프로비저닝 프로파일 1단계 3의 cp 명령으로 resources/embedded.provisionprofile에 두시고 "프로파일 넣었다"고만 말씀하시면 됩니다. 제가 그 자리에서 읽습니다. 옮기기가 번거로우면 내려받은 경로만 알려주셔도 제가 복사합니다. 아니요 — 공개 키와 App ID만 들어 있습니다. 서명에 쓰는 비밀키는 키체인에 있고 이 파일에 없습니다.
Google 클라이언트 ID 대화에 그대로 붙여 넣어 주세요. 예: 1234567890-abc….apps.googleusercontent.com 아니요 — 공개 클라이언트 ID입니다. 클라이언트 보안 비밀은 주지 마세요(쓰지 않습니다).
절대 보내지 마실 것: Apple ID 비밀번호, 앱 암호(xxxx-xxxx-xxxx-xxxx), .p12 인증서 파일과 그 암호, Google 클라이언트 보안 비밀. 전부 이미 키체인에 있거나 필요하지 않습니다. 업로드는 키체인의 AC_PASSWORD를 스크립트가 직접 읽어 쓰고, 값은 화면에도 로그에도 남지 않습니다.

그 뒤 제가 하는 것

  1. npm run mas:preflight — 6개 항목 전부 ✓ 확인.
  2. GOOGLE_OAUTH_CLIENT_ID=<주신 값> npm run mas:build — 유니버설(arm64 + x86_64) 서명 빌드, .pkg까지. 여기가 이번 진단에서 electron-builder를 26으로 올린 뒤 아직 실제로 못 돌려본 구간입니다 — 서명이 붙는 경로라 인증서 없이는 확인할 수 없었습니다. 깨지면 제가 고칩니다.
  3. 만들어진 앱을 실제로 띄워 샌드박스에서 동작하는지 확인 — 특히 Google 로그인의 루프백 콜백(샌드박스에서 리스닝 소켓이 열리는지는 서명 빌드로만 확인됩니다), 캘린더 동기화, 자동 업데이트가 꺼져 있는지, 전역 단축키가 꺼져 있는지.
  4. npm run mas:upload — 검증 후 App Store Connect 업로드. 이건 외부로 나가는 되돌리기 어려운 작업이라, 실행 전에 따로 확인받겠습니다.

제가 할 수 없는 것

  • developer.apple.com·Google 콘솔 로그인 — 그래서 위 2단계가 필요합니다.
  • App Store Connect에서 심사 제출 — 스크린샷·설명·가격·연령 등급은 웹에서 사람이 넣습니다. (스크린샷 12장은 이미 저장소에 있습니다 — docs/app-store/.)
  • 심사 답변 — com.apple.security.network.server를 왜 쓰는지 물어올 수 있습니다. 답변 문구가 docs/app-store-submission.md에 준비돼 있습니다(로그인 하는 동안만, 127.0.0.1에만 바인드).

참고 — 지금 당장 할 수 있는 다른 채널

직접 배포(다운로드) 채널은 Google ID만 있으면 바로 됩니다. 인증서·공증 자격증명·GitHub 토큰이 모두 준비돼 있어서, 프로비저닝 프로파일이 없어도 GOOGLE_OAUTH_CLIENT_ID=<값> npm run release로 서명·공증된 dmg를 만들어 GitHub 릴리스에 올릴 수 있습니다. App Store보다 빠른 길입니다.

GitHub Actions로 자동화하려면 시크릿 7개가 더 필요합니다(현재 HOMEBREW_TAP_TOKEN 하나만 등록됨) — CSC_LINK, CSC_KEY_PASSWORD, APPLE_API_KEY_B64, APPLE_API_KEY_ID, APPLE_API_ISSUER, APPLE_TEAM_ID, GOOGLE_OAUTH_CLIENT_ID. 로컬에서 릴리스한다면 없어도 됩니다. 필요해지면 그때 따로 안내하겠습니다.
