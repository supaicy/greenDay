먼저, 사실 확인 두 가지

haru에는 우리가 돈을 내는 서버가 없습니다

구독은 “매달 우리가 지출하는 것이 있다”에 대한 대가입니다. 그게 없으면 구독은 사용자에게 설명할 근거가 없고, 갱신 실패·환불·해지 흐름이라는 새 비용만 생깁니다. ₩19,000 평생가를 유지하는 것을 권합니다.

나중에 AI를 우리가 호스팅하게 되면 그건 별개 제품입니다 — 라이선스 서버는 이미 다제품 구조(products 테이블 + prod 클레임)라, greenday-ai 같은 slug를 하나 더 얹으면 됩니다. 지금 haru 본체를 구독으로 만들 이유는 되지 않습니다.

상태 기계

unlicensed ──(첫 평가)──▶ trial(until) ──(30일)──▶ trialExpired
     ▲                          │                      │
     │                          └──────활성화──────────┬┘
     │                                                 ▼
     └──(해제 / 서버 거부)───────────────────── licensed(until = 토큰 exp)
                                                       │ 오프라인으로 exp 통과
                                                       ▼
                                          grace(until = exp + 30일) ──▶ unlicensed

모든 허용 상태는 자기 마감을 들고 다닙니다. 매 접근마다 서명을 다시 검증하지 않기 위해서이고(ed25519 검증이 렌더러 요청 경로에 들어갑니다), 동시에 allowsPaid가 매번 자기 마감과 실제 시각을 비교하기 위해서입니다 — 6번 결함(“만료를 타이머로만 관리”)이 바로 이 비교를 생략해서 생겼습니다.

licensed가 자기 exp를 지나면 절벽이 아니라 유예로 떨어집니다. Electron 앱은 몇 주씩 안 꺼질 수 있고, 새벽 3시에 토큰이 만료된 유료 사용자를 “트라이얼이 끝났습니다” 화면으로 보내는 건 정확히 틀린 사람을 벌주는 것입니다.

저장 위치

userData/license.json — 할일 데이터(ticktick-data.json)와 다른 파일입니다. 이유 셋: 내보내기/가져오기가 라이선스를 실어 나르면 안 되고, 사용자가 데이터를 복원해도 라이선스가 되돌아가면 안 되며, QA용 데이터 백업이 라이선스 상태를 건드리지 않아야 합니다.

{ "key": "GREENDAY-…",   // 재검증에 쓸 키
  "token": "…",           // 서명된 활성화 토큰 — 유일한 권한 증거
  "lastSeen": 1755000000, // 본 적 있는 가장 나중 시각 (래칫)
  "trialStart": 1755000000 }

이 파일은 사용자가 열어 고칠 수 있습니다. 그래도 됩니다 — 상태는 서명 검증을 통과한 페이로드에서만 파생되므로, 손으로 쓸 수 있는 값 중 권한을 만드는 것은 하나도 없습니다. 파일을 통째로 지우면 트라이얼이 리셋되는데, 그건 BicMac과 같은 의도된 트레이드오프이고 문서에 그렇게 적습니다.

테스트 계획 — 6개 결함, 실패 테스트가 먼저

BicMac이 네 라운드에 걸쳐 만난 결함들입니다. 각각 RED 먼저 쓰고, 통과시킨 뒤 가드를 지워 다시 빨개지는지 확인합니다(뮤테이션).

#결함실패 테스트

천장도 통과 → allowsPaid가 false
트라이얼도 접근할 때마다 재계산

추가로 고정할 것

  • 거부와 불통의 구분. 409, 그리고 JSON 에러 봉투가 디코드되는 404는 라이선스를 닫는다. Cloudflare의 HTML 404, 타임아웃, 봉투 없는 400은 닫지 않는다 — 워커 배포 사고 한 번으로 전 사용자가 로그아웃되는 것이 최악의 실패다.
  • 반감기 갱신. iat + lifetime/2를 지났을 때만 네트워크를 친다. 실행마다 치면 오프라인 사용자가 매번 실패를 본다.
  • enforcement가 꺼져 있으면 아무것도 잠기지 않고 trialStart를 기록하지도 않는다. 이게 무료 기간을 정직하게 만든다 — 지금 쓰는 사람들의 30일이 살 것도 없는 상태에서 타들어가면 안 된다.
  • 기기 한도에 걸렸을 때 해제 버튼으로 나갈 수 있다. 안내만 하고 방법이 없으면 2대 한도가 지원 메일함이 된다.
