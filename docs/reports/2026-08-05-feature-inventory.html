높음 B-1. 타임블로킹을 만들 수 있는 경로가 없다

증상
README 대표 기능인 "할일을 캘린더 슬롯에 드래그해 시간 배정"을 사용자가 수행할 수 없습니다. 드래그 시작점(할일 목록의 TaskItem)과 드롭 대상(주/일 캘린더의 날짜 칼럼)이 MainContent의 viewType 스위치로 갈려 동시에 화면에 존재하지 않습니다.
측정값
리스트 뷰: 드래그 가능한 할일 행 6개 / 날짜 칼럼 0개.
주간 캘린더 뷰: 날짜 칼럼 7개 / 드래그 가능한 요소 0개.
사용자 DB의 기존 할일 25건 중 scheduled_start를 가진 것 0건 — 기능이 한 번도 쓰인 적 없음.
드롭 핸들러 자체는 정상
QA에서 application/haru-task-id를 직접 넣어 드롭했더니 2026-08-06T10:30~11:00 블록이 정상 생성·렌더됐습니다. 생성된 블록의 이동(길이 30분 유지)과 우클릭 → 일정 해제도 정상입니다. 소비자는 멀쩡하고 생산자(진입점)만 없습니다.
위치
TaskItem.tsx:93이 유일한 TASK_ID 생산자 · WeeklyCalendar.tsx:361 / DailyCalendar.tsx:285가 유일한 소비자 · App.tsx:27 뷰 스위치
