1 배포 순서 — 당신이 진행할 단계

Phase 0 · 선행조건 당신

  • Apple Developer Program 가입 ($99/년) — developer.apple.com/programs
  • Team ID 확인 (Membership 페이지), xcode-select --install

Phase 1 · 식별자 + 앱 레코드 당신

  • Apple Developer → Identifiers에 Bundle ID com.haru.app 등록 (이미 선점됐으면 com.<yourteam>.haru로 바꾸고 electron-builder.yml의 appId도 수정)
  • App Store Connect → 새 앱 생성: 이름(haru), Bundle ID, SKU, 기본 언어

Phase 2 · 인증서 + 프로비저닝 당신

  • Apple Distribution 인증서 (앱 서명)
  • 3rd Party Mac Developer Installer 인증서 (.pkg 서명) — 없으면 MAS 빌드 실패
  • Mac App Store 프로비저닝 프로파일 생성 → resources/embedded.provisionprofile로 저장 (electron-builder 자동 인식)

Phase 3 · 빌드 설정 준비됨

  • NODE_OPTIONS="--dns-result-order=ipv4first --no-network-family-autoselection" npm run package:mas
  • 결과: dist/mas-arm64/haru-2.0.0.pkg (Apple Distribution + Installer 인증서로 서명됨)
  • (선택) Intel 포함하려면 universal 빌드 — --x64 추가 또는 universal 타겟

Phase 4 · 업로드 + 메타데이터 당신

  • Transporter(Mac App Store 앱) 또는 xcrun notarytool/altool로 .pkg 업로드
  • App Store Connect에 스크린샷(1280×800 등), 설명, 키워드, 개인정보 처리방침 URL, 가격/지역 입력
  • App Privacy: haru는 로컬 저장 + 온디바이스 AI라 기본 "데이터 수집 안 함". 단 외부 provider(OpenAI 등) 옵션이 있으므로 "선택 시 외부 전송" 고지 검토 (로컬 전용 잠금 기능이 있어 유리)

Phase 5 · 심사 제출 + 대응 당신

  • 심사 제출
  • 심사 노트 권장: AI 기능은 사용자가 별도 설치한 로컬 Ollama 서버(localhost)에 접속. Ollama 미설치여도 앱은 정상 동작(AI만 비활성). 심사관이 AI를 테스트하려면 Ollama 설치가 필요함을 명시
재제출 주의: 같은 버전을 다시 업로드하려면 CFBundleVersion(빌드 번호)이 매번 증가해야 합니다. electron-builder는 version을 그대로 쓰므로, 재빌드 시 package.json의 version을 올리거나 electron-builder.yml에 buildVersion을 따로 관리하세요.

2 요약 · 남은 블로커

코드/설정/빌드 파이프라인은 준비 완료. 유일한 블로커는 Apple Developer 계정과 3종 인증서(+프로비저닝) — 전부 Apple 로그인이 필요한 당신의 영역입니다. 인증서를 resources/embedded.provisionprofile로 넣고 npm run package:mas를 돌리면 서명된 .pkg가 나오고, Transporter로 올리면 됩니다. 전체 세부 절차는 리포지토리의 docs/DEPLOYMENT.md에도 정리돼 있습니다.

검증 커밋: MAS 업데이트 UI 51f1bad. 빌드 산출물 dist/는 gitignore. 이 계획은 코드가 아니라 계정/인증서 단계라 제가 대신 수행할 수 없어 순서로 안내합니다 — 각 Phase에서 막히면 알려주세요.
