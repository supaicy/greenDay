TL;DR — 세 평가가 독립적으로 같은 결론에 도달했습니다: 이 패널의 가장 큰 문제는 색이나 아이콘이 아니라 공간 배분입니다. 빈 메모가 패널의 67%(534px)를 먹고, 실제 할 일인 하위작업·첨부는 바닥 15%로 밀려 있습니다. 두 번째는 메타 스트립이 flex-wrap이라 기본 폭 400px에서 이미 세 줄로 깨진다는 것입니다. 셋 다 지목한 항목이 5개이고, 그중 넷은 수치까지 일치합니다.

0 · 평가 대상 화면

평가는 시각 디자인과 정보 배치에 한정했습니다. 코드 품질·버그는 앞선 리뷰 라운드(/simplify, /review, /code-review, Codex 교차리뷰)에서 이미 다뤘고, 이번 프롬프트에서 제외했습니다.

1 · 세 평가가 합의한 것 3/3 합의

서로의 결과를 모르는 상태에서 셋 다 짚은 항목입니다. 신뢰도가 가장 높고, 여기부터 손대는 게 맞습니다.

① 빈 메모가 패널의 3분의 2를 먹는다 — 최우선

현재: TaskDetail.tsx:387-406에서 메모가 flex-1, 하단 블록이 flex-shrink-0 max-h-[38%]입니다. 메모가 남는 높이를 전부 가져가므로, 글자 두 개만 적힌 메모가 534px(67%)를 차지하고 하위작업·첨부는 120px(15%)로 눌립니다.

사용자가 겪는 것: 빈 태스크를 열면 화면 한가운데가 아무 표시 없는 회색 면입니다. 클릭해서 커서가 뜨기 전까지 여기가 입력란인지 알 수 없고, 정작 할 일(하위작업 추가)은 시선을 바닥까지 옮겨야 보입니다.

세 평가의 처방이 같습니다 — 본문을 스크롤 컨테이너 하나로 합치고, 메모는 최소 높이만 보장한 뒤 내용만큼 자라게 합니다.

<div className="flex-1 min-h-0 overflow-y-auto">
  <div className="min-h-[7.5rem] px-4 py-3"><AtomicCodeMirrorEditor … /></div>
  <div className="border-t px-4 py-3"><SubtaskList … /><AttachmentList … /></div>
</div>

덧붙여 CM6 placeholder()를 붙여 "메모 추가…"를 띄우면 빈 면이 편집 영역임을 알립니다. 디자인 렌즈는 여기에 더해 메모에 bg-surface-canvas(#1C1C1E) 면을 깔아 figure/ground를 만들라고 제안했습니다.

② 메타 스트립이 폭에 따라 요동친다 — 기본 폭에서 3줄

현재: TaskDetail.tsx:245의 flex flex-wrap items-center gap-2에 성격이 다른 컨트롤 6종이 순서만 정해진 채 흘러듭니다.

실측: 캡쳐한 624px에서 2줄인데, 기본 폭 400px에서는 3줄입니다(콘텐츠 368px에 마감일 141+시간 74+우선순위 172+리스트 92+알림 56+반복 56+태그 160). 즉 대부분의 사용자가 보는 기본 상태가 캡쳐보다 어지럽습니다.

결과: 줄바꿈 위치가 폭·번역 길이·알림 설정 여부에 따라 계속 바뀌어 속성의 위치를 학습할 수 없습니다. 게다가 반복(scheduling)이 태그(classification) 옆으로 밀려 의미 그룹이 깨집니다.

처방(3인 공통): 라벨 2열 그리드로 고정합니다.

<div className="grid grid-cols-[4.5rem_minmax(0,1fr)] gap-x-3 gap-y-1.5 px-4 py-3">
  <span>마감일</span>   <div>날짜 + 시각</div>
  <span>우선순위</span> <div>…</div>
  <span>목록</span>     <div>…</div>   … 알림 / 반복 / 태그
</div>

높이는 90px → 약 170px로 늘지만, 그 예산은 ①에서 회수한 메모 공간에서 그대로 나옵니다. 지금은 어느 컨트롤이 무엇인지 알려주는 라벨이 하나도 없다는 점도 함께 해결됩니다.

③ 제목이 잘리는데 말줄임도 툴팁도 없다

현재: TaskDetail.tsx:218-225가 <input type="text">입니다. input은 넘치는 글자를 캐럿 기준으로 스크롤할 뿐이라 "…/ google-serv"에서 그냥 끊깁니다. title 속성도 없습니다.

가장 아픈 지점: 가운데 목록에서는 같은 제목이 두 줄로 온전히 보입니다. 즉 상세를 열면 목록보다 정보가 줄어듭니다. 기본 폭 400px에서는 15자 남짓만 남습니다.

처방: 두 줄까지 자라는 textarea로 교체합니다(Chromium 13x이라 field-sizing: content 사용 가능). 기존 Enter→blur는 유지하되 IME 조합 가드를 함께 넣습니다.

<textarea rows={1} title={title}
  className="flex-1 min-w-0 bg-transparent text-lg font-semibold outline-none
             resize-none [field-sizing:content] max-h-[3.5rem] leading-snug" />

네이티브 <select>만 이질적 (디자인 렌즈 + Codex)

처방: select를 드롭다운 메뉴로 교체(트리거는 pickerBtnCls). 컨트롤 언어가 하나 줄고 팝오버 모서리도 저절로 맞습니다.

우선순위가 "필터 툴바"처럼 보인다 (디자인 렌즈 + Codex)

네 칩을 항상 노출하고 선택된 것만 유색 면을 가집니다. 그 결과 가장 채도 높은 물체가 "낮음"이 되어, 18px 흰 제목보다 먼저 눈에 들어옵니다. 게다가 헤더의 완료 원도 같은 파랑이라 낮은 우선순위 태스크에서 파랑이 두 번 발화합니다.

처방(두 갈래): ⓐ 깃발 아이콘 + 값 + chevron의 단일 트리거로 줄여 팝오버에서 고르게 하거나(폭 100px 회수, 목록의 ⚑ 낮음 표기와 언어 통일), ⓑ 세그먼티드 컨트롤로 묶되 low/none은 채운 면 대신 테두리로 선택을 표시합니다.

3 · 한 평가만 짚은 것 1/3

합의가 없다고 틀린 건 아닙니다. 다만 근거가 한 갈래뿐이라 판단이 더 필요합니다.

출처지적근거
엔지니어마감일을 DueDatePicker로 교체 — "오늘/내일/다음 주" 빠른 선택이 없어 매번 연·월·일을 타이핑한다. 지우기 X가 값이 있을 때만 나타나 폭이 14px 변하고 그 순간 스트립 전체가 재줄바꿈된다할일 앱에서 가장 잦은 조작인데 경로가 가장 원시적. 215px 점유
엔지니어스크롤 컨테이너가 둘 — 메모는 CM6 내부, 하단은 max-h-[38%] overflow-y-auto. 휠이 커서 위치에 따라 다르게 동작①의 처방으로 함께 해소됨
엔지니어리사이즈 핸들이 키보드 첫 탭 스톱인데 아무 일도 안 한다 — onMouseDown만 있음. 화살표 키 리사이즈 + 더블클릭 기본값 복귀 제안DOM 순서상 패널의 첫 포커스 요소. 폭을 흐트러뜨리면 400으로 되돌릴 방법이 없음
엔지니어드래그 중 커서·선택이 샌다 — 핸들을 끌면 메모 위에서 I-beam으로 바뀌고 본문이 파랗게 선택됨. body.style.cursor/userSelect 미설정8px 핸들이라 조준도 빡빡함 → 12px 제안
엔지니어하위작업 추가가 두 번 클릭 — showInput 토글. 두 요소 높이가 같아 공간 이득 0인데 클릭만 늘어남. 가운데 목록은 항상 열린 입력상태 하나·이펙트 하나가 같이 사라짐
디자인값 없는 필드가 가장 시끄럽다 — 빈 날짜/시각이 surface-sunken(#3A3A3C, 패널보다 밝음) 위에 네이티브 placeholder를 띄워, 데이터가 없는데 패널이 차 보인다우선순위 칩은 border-transparent로 올바르게 사라짐 — 같은 규칙 적용 제안
디자인medium 노랑이 세 가지 — yellow-400(priority.ts:8, TaskItem.tsx:11)와 amber-300/500(PRIORITY_SURFACE, PRIORITY_COLOR)이 공존amber로 통일하고 TaskItem의 로컬 맵 삭제
디자인삭제 버튼이 닫기와 8px 간격, 확인 없이 즉시 실행휴지통+Undo가 있어 데이터 손실은 아니나 패널이 닫혀 위치를 잃음
Codex시각 입력 아이콘만 검게 남아 비활성처럼 보인다 — 날짜만 picker indicator 보정, 시각은 미보정color-scheme: dark + 양쪽에 동일 filter 적용

5 · 이번에 이미 고친 것

  • 달력 아이콘 중복 제거 — 마감일 앞 lucide Calendar와 <input type="date">의 네이티브 글리프가 나란히 두 개 보였습니다. 장식 아이콘을 걷어내고 의미는 aria-label로 남겼습니다(5397140).
  • 선택 행의 남색 제거 — 목록에서 선택된 행이 bg-primary-900/30이라 옆 패널(#2C2C2E)과 계열이 갈렸습니다. 중립색으로 통일하고 선택은 왼쪽 우선순위 액센트 바로 표시합니다(3f73445).
  • 우선순위 면색 — 상세 화면에서 선택된 등급에 면색+테두리를 넣어 한눈에 읽히게 했습니다. 다만 위 3장에서 보듯 "낮음"이 가장 채도 높은 물체가 되는 부작용이 지적됐으니, 5·6번 작업 때 함께 조정하는 게 좋습니다.
