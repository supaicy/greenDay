전제동의하시는지 확인할 네 가지

아래 넷은 제가 확인한 사실 위에 세운 전제입니다. 하나라도 틀리면 결론이 달라지니, 동의 안 되시는 게 있으면 말씀해 주세요.

전제 1 · 동기화는 사장님에게 원가가 0원입니다

코드를 확인했습니다. iCloud는 calendar-config.ts:31에서 caldav.icloud.com에 직접 붙고, Google은 google/oauth.ts:16의 accounts.google.com과 google/calendar.ts:11의 googleapis.com/calendar/v3에 직접 붙습니다. 중간에 사장님 서버가 없습니다. Google Calendar API는 무료이고 하루 100만 요청까지 과금이 없습니다. 사용자가 100명이든 10만 명이든 사장님이 내는 돈은 0원입니다.

즉 "Google은 돈이 더 드니까 따로 받는다"는 성립하지 않습니다. 따로 받으려면 비용이 아닌 다른 명분이 있어야 하고, 그게 뭔지가 아래 D안의 쟁점입니다.

전제 2 · 사람들이 요청한 축은 기능이 아니라 플랫폼입니다

받으셨다는 요청 세 가지를 그대로 옮기면:

  1. 윈도우에서 쓰게 해달라 — 플랫폼
  2. 다양한 캘린더·플랫폼과 연동되게 해달라 — 플랫폼
  3. 경쟁사에 있는 기능을 넣어달라 — 이건 "TickTick을 공짜로 달라"입니다

아무도 이미 만든 기능에 돈을 내겠다고 하지 않았습니다. 사람들이 반응한 문장은 전부 "내가 있는 곳에서 되게 해달라"입니다. 그렇다면 캘린더 연동을 잘라 유료 벽 뒤로 넣는 건 요청 2위를 정확히 거꾸로 처리하는 것입니다.

전제 3 · 지금 병목은 가격이 아니라 아무도 이 앱을 모른다는 것입니다

유입이 클리앙 한 곳뿐이고 월 45명입니다. 이슈는 5개월간 0건입니다. 스타 2개입니다. 목표까지 140~460배입니다. 가격 손잡이를 아무리 돌려도 이 숫자는 안 움직입니다.

전제 4 · Windows는 이 코드베이스에서 싼 편입니다

메인 프로세스에서 macOS 전용 코드는 8줄입니다 — titleBarStyle: 'hiddenInset', process.platform !== 'darwin' 분기 하나, 그리고 나머지는 전부 process.mas(App Store 전용) 분기입니다. 쓰고 있는 Electron API — safeStorage, globalShortcut, Notification — 는 전부 Windows에서 동작합니다. electron-builder.yml에 win: 타겟이 없을 뿐입니다.

드는 것: NSIS 타겟 추가, 타이틀바 분기, 알림용 AppUserModelId 설정, 그리고 코드 서명 인증서(EV 인증서 연 30~50만원, 또는 Azure Trusted Signing 월 1만원대). 서명 없이 내면 Windows SmartScreen이 막습니다 — macOS Gatekeeper와 같은 상황입니다.
