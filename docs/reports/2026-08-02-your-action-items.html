사장님이 직접 하셔야 하는 일

2026-08-02 · Greenday v2.0.1 · 코드 작업은 전부 끝났습니다 · 번들 ID com.supaicy.haru

아래 6가지는 제가 대신 할 수 없는 것들입니다. Apple·Google 계정 로그인과 2단계 인증이 필요하거나, 결제·법적 동의가 얽혀 있기 때문입니다. 나머지는 전부 코드에 반영해 뒀습니다.

번들 ID가 바뀌었습니다. com.Greenday.app은 이미 다른 개발자가 선점해 쓸 수 없어서 com.supaicy.haru로 바꿨습니다 (기존 com.supaicy.bicmac과 같은 네임스페이스). 코드·빌드 설정·이 문서에 전부 반영했습니다.

기존 사용자 데이터는 그대로입니다. 확인해 봤는데 할 일 저장 위치는 ~/Library/Application Support/ticktick/이고, 이 경로는 번들 ID가 아니라 앱 이름으로 정해집니다. 번들 ID를 바꿔도 데이터는 이사 가지 않습니다.

다만 macOS 입장에서는 다른 앱이 되므로, 새 빌드가 기존 /Applications/Greenday.app을 덮어쓰지 않습니다. 새로 설치하실 때 예전 것을 먼저 지워 주세요 (안 지우면 두 개가 공존합니다).
순서가 중요합니다. ①②③은 서로 물려 있어 이 순서대로 하셔야 합니다. ④는 지금 바로 시작해두면 좋고(심사 대기가 있음), ⑤⑥은 아무 때나 하셔도 됩니다.

① App ID 등록

1 Bundle ID com.supaicy.haru 만들기 약 5분

developer.apple.com → Certificates, Identifiers & Profiles → Identifiers

  1. + 버튼 → App IDs → App 선택
  2. Description: Greenday
  3. Bundle ID: Explicit 선택 후 com.supaicy.haru 입력
    정확히 이 값이어야 합니다. 앱의 Info.plist·프로비저닝 프로파일· App Store Connect 레코드 세 곳이 전부 이 값으로 맞아야 업로드가 통과합니다. 오타가 있으면 빌드는 성공하고 업로드에서 거절됩니다.
  4. Capabilities: 아무것도 체크하지 마세요. Greenday는 iCloud·푸시·Sign in with Apple을 쓰지 않습니다. 필요 없는 걸 켜면 심사에서 사유를 묻습니다.
  5. Continue → Register

② 프로비저닝 프로파일

2 Mac App Store 프로파일 재발급 약 5분 · ①이 끝나야 가능

developer.apple.com → Profiles

  1. + → Distribution 아래 Mac App Store Connect 선택
  2. App ID: 방금 만든 com.supaicy.haru 선택
  3. Certificate: Apple Distribution: MINSEOK SHIN 선택
  4. Profile Name: Greenday MAS (아무 이름이나 괜찮습니다)
  5. Generate → Download
  6. 받은 파일을 이 경로에 저장: 
    ~/orca/workspaces/ticktick/coordinate/resources/embedded.provisionprofile
    파일 이름을 정확히 embedded.provisionprofile로 바꿔 주세요.

맞게 하셨는지 확인하는 방법. 터미널에서 이 명령을 실행하세요:

cd ~/orca/workspaces/ticktick/coordinate && npm run mas:preflight

전부 ✓가 나오면 성공입니다. 프로파일이 다른 앱 것이면 ✗ 프로파일이 다른 앱의 것입니다라고 잡아 줍니다 — 지난번에 BicMac 프로파일로 겪으셨던 그 문제를 여기서 미리 거릅니다.

통과하면 바로 빌드할 수 있습니다: npm run mas:build
이 프로파일 파일은 개인 자격증명이라 git에 올라가지 않도록 제외해 뒀습니다.

    이 범위를 고른 이유. 흔히 쓰는 calendar.events는 사용자의 기존 캘린더까지 읽을 수 있어서 구글의 민감 범위 심사 대상이 됩니다 — 보안 평가와 데모 영상까지 요구받습니다. calendar.app.created는 Greenday가 만든 일정만 다루는 범위라 비민감으로 분류되고, 우리에게 필요한 기능은 전부 됩니다. 심사 부담을 크게 줄이려고 일부러 이 범위로 구현했습니다.
  5. 사용자 인증 정보 → OAuth 클라이언트 ID 만들기
    항목값
    애플리케이션 유형iOS
    번들 IDcom.supaicy.haru
    "데스크톱 앱"이 아니라 "iOS"입니다. 헷갈리기 쉬운데, 구글에서 커스텀 URL 스킴으로 콜백을 받는 클라이언트는 iOS 유형으로 만들어야 합니다. 데스크톱 앱 유형은 루프백 서버(http://127.0.0.1:포트) 방식이라, 그걸 쓰면 앱이 로컬 서버를 열어야 하고 Mac App Store 심사에서 "왜 서버를 여느냐"는 질문을 받게 됩니다.
  6. 발급받은 클라이언트 ID를 알려주세요. 123456-abc.apps.googleusercontent.com 같은 형태입니다. 제가 빌드에 넣겠습니다.
    이 값은 비밀이 아닙니다. 데스크톱 앱은 시크릿을 숨길 수 없어서 구글도 공개 클라이언트로 쓰도록 하고 있고, 대신 PKCE라는 방식으로 보호합니다. 그래서 앱에 담겨 배포돼도 안전합니다 — 이미 그렇게 구현해 뒀습니다.

⑤ v2.0.1 공개 여부

5 결정만 하시면 됩니다 1분

지난번에 서명·공증까지 마친 v2.0.1이 GitHub에 비공개(draft) 상태로 올라가 있습니다. 지금은 아무도 받을 수 없습니다.

선택결과
A. 지금 공개 웹에서 바로 받을 수 있게 됩니다. 다만 한/영 지원과 캘린더 동기화가 빠진 버전이고, 번들 ID도 옛날 것(com.Greenday.app)입니다. 받은 사람은 나중에 새 버전을 설치할 때 옛 앱을 따로 지워야 합니다.
B. 기다렸다 v2.1.0으로 권장 새 기능과 새 번들 ID를 한 번에 담아 공개. 첫인상도 좋고, 사용자가 앱을 두 번 지우고 설치하는 일도 없습니다.

A를 고르시면 이 명령입니다:

gh release edit v2.0.1 --draft=false --latest
미리 말씀드리면 — 공개하는 순간 GitHub Actions가 한 번 돌고 빨간 X로 실패합니다. 배포용 시크릿을 등록하지 않으셨기 때문인데, 이건 고장이 아닙니다. 릴리스 파일은 이미 다 올라가 있어서 사용자 다운로드에는 아무 영향이 없습니다. 워크플로가 시작하자마자 "시크릿 없음"으로 스스로 멈추는 것뿐입니다.

⑥ 실제 계정으로 동기화 테스트

6 제가 못 하는 검증 약 10분 · 권장

캘린더 동기화 코드는 387개 테스트로 검증했지만, 그건 전부 가짜 서버를 상대로 한 것입니다. 진짜 Apple 서버에 붙는 것만은 사장님 계정으로만 확인할 수 있습니다 — 제가 사장님 Apple ID로 로그인할 수는 없기 때문입니다.

  1. account.apple.com에서 앱 암호를 하나 새로 발급 (이름: Greenday 캘린더)
    이전에 만드신 앱 암호를 재사용하셔도 됩니다. 앱마다 따로 만들면 나중에 하나만 취소하기 쉬워서 새로 만드는 걸 권합니다.
  2. Greenday 실행 → 설정 → 캘린더 동기화
  3. Apple ID와 방금 만든 앱 암호 입력 → 연결 확인
  4. 캘린더 목록이 뜨면 하나 고르기 (미리알림은 목록에 안 나옵니다 — 일정을 담을 수 없어서 제외했습니다)
  5. 마감일이 있는 할 일을 하나 만들고 → 지금 동기화
  6. iPhone 캘린더 앱에서 그 할 일이 보이는지 확인

확인해 주셨으면 하는 것:

  • 한글 제목이 깨지지 않는지 (줄바꿈 규칙을 바이트 단위로 처리했는데, 실제 애플 서버 반응은 확인이 필요합니다)
  • 종일 할 일이 하루짜리로 보이는지 (이틀에 걸쳐 보이면 알려주세요)
  • 할 일을 수정하고 다시 동기화했을 때 새 일정이 생기지 않고 기존 게 바뀌는지

안 되는 게 있으면 화면에 나온 오류 문구를 그대로 알려주세요. 오류마다 다른 안내가 나오게 해 뒀습니다.
