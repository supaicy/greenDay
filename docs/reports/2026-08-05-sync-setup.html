동기화 준비할 것

동기화가 두 종류인데 준비할 게 있는 건 한쪽뿐입니다.

iCloud — 준비할 것 없음

✓ 지금 그대로 동작합니다

사용자가 자기 Apple ID와 앱 암호를 직접 입력하는 방식이라, 사장님이 등록하거나 신청할 것이 하나도 없습니다. 개발자 계정도, API 키도, 승인 절차도 필요 없습니다.

앱이 caldav.icloud.com 에 직접 붙습니다. 중간에 아무것도 없습니다. 사용자는 account.apple.com 에서 앱 암호를 하나 만들어 넣기만 하면 됩니다.

Google — 여기만 준비가 필요합니다

구글은 앱 단위로 등록을 요구합니다. 사용자별이 아니라 사장님이 한 번 등록하면 모든 사용자가 그걸 씁니다.

4. 범위(Scope) 추가 — 딱 이것 하나만

https://www.googleapis.com/auth/calendar.app.created
추가하실 때 화면에 뜨는 등급을 알려주세요. 구글 콘솔은 범위마다 민감(Sensitive) / 제한(Restricted) / 일반 여부를 표시합니다. 이 범위는 앱이 만든 일정만 다루는 가장 좁은 것이라 일부러 골랐지만, 구글의 분류가 바뀌었을 수 있어 화면에 실제로 뭐라고 나오는지 확인이 필요합니다.

민감으로 뜨면 검증 절차(신청서 + 데모 영상)가 붙습니다. 며칠~몇 주 걸립니다. 일반으로 뜨면 그냥 게시하면 됩니다.

어느 쪽이든 calendar.events(사용자의 기존 일정까지 읽는 범위)보다는 훨씬 가볍습니다. 그래서 이 범위로 구현해 뒀습니다.

5. OAuth 클라이언트 ID 만들기

APIs & Services → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID

항목값
애플리케이션 유형iOS
번들 IDcom.supaicy.haru
두 가지를 헷갈리기 쉽습니다.

① "데스크톱 앱"이 아니라 "iOS"입니다. 맥 앱인데 왜 iOS냐 싶으시겠지만, 구글에서 커스텀 URL 스킴으로 콜백을 받는 클라이언트는 iOS 유형으로 만들어야 합니다. 데스크톱 앱 유형은 로컬 서버를 여는 방식이라, 그걸 쓰면 Mac App Store 심사에서 "왜 서버를 여느냐"는 질문을 받게 됩니다.

② 번들 ID는 com.supaicy.haru 입니다. Greenday가 아닙니다. 앱 이름과 번들 ID를 일부러 다르게 뒀습니다. 여기가 어긋나면 브라우저에서 로그인은 성공하는데 앱으로 돌아오지 못합니다 — 화면에 오류도 안 뜨고 그냥 계속 기다리기만 해서 원인 찾기가 가장 어려운 종류입니다.

6. 발급받은 클라이언트 ID를 저에게 알려주세요

123456789-abcdefg.apps.googleusercontent.com

이런 형태입니다. 빌드에 넣어드리겠습니다.

이 값은 비밀이 아닙니다. 데스크톱 앱은 시크릿을 숨길 수 없어서 구글도 공개 클라이언트로 쓰도록 하고 있고, 대신 PKCE라는 방식으로 보호합니다. 앱에 담겨 배포돼도 안전하고, 이미 그렇게 구현해 뒀습니다.

지금 상태에서 Google을 빼고 출시할 수 있습니다

클라이언트 ID가 없으면 앱은 설정 화면에 "이 빌드에는 Google 연동이 설정되어 있지 않습니다" 라고만 표시하고 나머지는 정상 동작합니다. 오류도 빈 화면도 나오지 않습니다.

그래서 iCloud 동기화만으로 먼저 출시하고, 구글 심사가 끝난 뒤 다음 버전에 넣는 것도 가능합니다. 구글 쪽 대기 때문에 앱스토어 출시가 늦어질 이유는 없습니다.
