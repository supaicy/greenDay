## 서명

```
$ codesign -d -r- haru.app
# designated => cdhash H"98f1848815b813e3a8712de784d42f1cbd2aca0c"

$ codesign -dvv haru.app
Identifier=Electron
Format=app bundle with Mach-O thin (arm64)
CodeDirectory v=20400 size=392 flags=0x20002(adhoc,linker-signed) hashes=9+0 location=embedded
Signature=adhoc
Info.plist=not bound
TeamIdentifier=not set
Sealed Resources=none

$ spctl -a -vv -t exec haru.app
haru.app: code has no resources but signature indicates they must be present
```

- **Team ID 없음.** Developer ID 로 서명된 적이 없다 — 링커가 붙인 ad-hoc 서명뿐이다.
- 서명 식별자가 `Electron` 이다(우리 번들 ID가 아니다). Info.plist 도 서명에 묶여 있지 않다.
  즉 electron-builder 의 서명 단계가 아예 돌지 않은 채 나간 빌드다. README 의
  "인증서로 서명되지 않았으니 `xattr -cr`" 안내와 일치한다.
- **Designated requirement 가 cdhash 하나다.** 이 DR 은 바이너리가 1비트라도 바뀌면 다른 앱이다.

## 이것이 마이그레이션 계획에 뜻하는 것

1. **저장소의 `com.supaicy.haru` 는 한 번도 배포되지 않았다.** 배포된 것은 `com.haru.app` 뿐이다
   (docs/27 의 결론이 실물로 확인됐다). 다음 릴리스는 어느 ID 로 나가든 v1.4.1 사용자의
   자동 업데이트 연속성을 잃는다 → `com.begreen.greenday` 로 가는 비용이 추가로 들지 않는다.
2. **Keychain ACL 프롬프트는 번들 ID 와 무관하게 어차피 뜬다.** v1.4.1 의 DR 이 cdhash 라서,
   같은 번들 ID 로 내더라도 새 바이너리는 옛 ACL 에 없다. 게다가 Team ID 가 없으니
   "같은 팀의 앱" 규칙으로도 이어지지 않는다. 브리지 릴리스가 sentinel 을 만든다 해도
   그 릴리스 자체가 새 바이너리라 프롬프트를 한 번 받는 것은 피할 수 없다.
3. **다만 v1.4.1 사용자에게 `ticktick Safe Storage` 항목이 있을 가능성은 낮다.** `safeStorage`
   는 2.0.0(미공개)에서 들어왔고 v1.4.1 코드는 부르지 않는다. Chromium 의 OSCrypt 는 첫
   encrypt/decrypt 호출 때 Keychain 키를 만들므로, v1.4.1 만 쓴 사용자는 항목이 없다 →
   새 앱이 새 키를 만들고 끝난다. 복호화할 옛 암호문이 없다. safeStorage 위험은
   **2.0.0 이후 빌드를 로컬에서 써 온 개발자 본인의 맥**에 국한된다.
4. **Electron 내부 앱 이름 `ticktick` 은 그대로 둬야 한다**는 처방은 유효하다 — userData 가
   `~/Library/Application Support/ticktick` 이고 새 앱이 같은 곳을 읽어야 데이터가 이어진다.
5. `LSMinimumSystemVersion` 12.0 은 이미 배포본에 들어가 있었다. 이번에 `electron-builder.yml`
   의 `minimumSystemVersion: '12.0'` 으로 명시한 것은 값의 변경이 아니라 못박기다.
6. 커스텀 스킴은 배포된 적이 없으므로(`CFBundleURLTypes` 없음) 스킴 이름을 바꿔도 옛 링크가
   깨질 것이 없다.

## 아직 못 본 것

- **Keychain 의 실제 service/account 이름.** 앱을 실행하지 않았고, 이 맥의 로그인 Keychain 을
  뒤지는 것은 사용자 데이터라 하지 않았다. Chromium 규약상 `<app.getName()> Safe Storage` =
  `ticktick Safe Storage` 이며, 위 3 의 이유로 v1.4.1 사용자에게는 항목 자체가 없을 것이다.
  확인하려면: `security find-generic-password -s "ticktick Safe Storage"` (본인 맥에서).
