미검증 항목 대장

Greenday v2.0.1 · 2026-08-05 · 전체 검증 결과는 기능 인벤토리 참조

2026-08-05 전수 검증에서 끝까지 확인하지 못한 5가지입니다. 전부 "코드가 의심스러워서"가 아니라 외부 자격증명이나 다른 빌드 구성이 없어서 막힌 것들입니다. 조건이 갖춰지는 시점에 이 문서만 보고 바로 검증할 수 있게 필요한 준비물과 절차를 적어 뒀습니다.

이 5가지는 결함이 아닙니다. 확인된 결함 13건은 인벤토리 문서 2절에 따로 있습니다. 여기 있는 항목은 "동작할 것으로 보이지만 눈으로 확인하지 못한 상태"입니다.

1. 소유자 준비가 필요한 것

차단 U-1. Google 캘린더 동기화

현재 상태
설정 화면에 "이 빌드에는 Google 연동이 설정되어 있지 않습니다"만 표시됩니다. 빌드 타임 상수 __GOOGLE_CLIENT_ID__와 환경변수 GOOGLE_OAUTH_CLIENT_ID 모두 비어 있어 clientIdConfigured가 false입니다.
이미 확인된 부분
OAuth PKCE 흐름 · 토큰 갱신/폐기 · 캘린더 목록 필터(쓰기 가능만) · 동기화 계획 로직 — 전부 유닛테스트 통과. UI 렌더링과 버튼 배선도 코드 확인 완료. 남은 건 실제 왕복뿐입니다.
필요한 준비물
Google Cloud Console에서 데스크톱 앱(공개 클라이언트) OAuth 클라이언트 ID 발급. 리디렉션은 커스텀 스킴이므로 번들 ID com.supaicy.haru를 등록해야 합니다 (앱 이름 Greenday와 번들 ID가 다릅니다 — 실수하기 쉬운 지점).
검증 절차
  1. GOOGLE_OAUTH_CLIENT_ID=<발급값> 주입 후 재빌드
  2. 설정 → Google 캘린더 → 연결 → 브라우저 동의 → 앱으로 복귀되는지 (U-2 동시 검증)
  3. 캘린더 목록 불러오기 → 쓰기 가능한 것만 나오는지
  4. 캘린더 선택 → 지금 동기화 → 생성/수정/삭제 요약 숫자와 실제 Google 캘린더 대조
  5. 연동 해제 → 토큰이 서버에서도 회수되는지(재연결 시 다시 동의 요구)

차단 U-2. 커스텀 스킴 딥링크 복귀

현재 상태
Google OAuth 콜백 전용 경로라 U-1에 종속됩니다. 루프백 서버를 열지 않고 app.setAsDefaultProtocolClient + open-url로 받도록 되어 있습니다 (MAS 샌드박스에서 network.server 권한을 피하려는 설계).
검증 절차
U-1의 2단계에서 브라우저 동의 후 앱 창이 자동으로 앞으로 나오고 최소화 상태면 복원되는지까지 확인. 개발 모드와 패키징 모드의 등록 경로가 다르므로(is.dev 분기) 양쪽 다 확인해야 합니다.

보류 U-3. CalDAV(iCloud) 캘린더 동기화

현재 상태
UI는 완성돼 있습니다(Apple ID · 앱 암호 입력, 연결, 캘린더 선택, 지금 동기화, 연동 해제). 실제 iCloud 계정이 없어 서버 왕복만 미확인입니다.
이미 확인된 부분
CalDAV 프로토콜 4개 모듈(client · dav-xml · ical · sync) 유닛테스트 전부 통과. 비밀번호가 safeStorage로 암호화 보관되고 toPublicConfig가 렌더러로 절대 넘기지 않는 것도 코드 확인.
필요한 준비물
Apple ID + 앱 전용 암호(일반 비밀번호 아님). 설정 화면의 "앱 암호 만들기" 링크에서 발급 가능.
검증 절차
  1. Apple ID + 앱 암호 입력 → 연결 → 캘린더 목록이 나오는지 (일정 담기 불가한 컬렉션은 걸러져야 함)
  2. 캘린더 선택 → 지금 동기화 → iCloud 캘린더 앱에서 일정 확인
  3. 할일 제목·마감일 수정 → 재동기화 → 기존 일정이 수정되는지 (중복 생성 아님)
  4. 할일 삭제 → 재동기화 → 일정도 사라지는지
  5. 다른 캘린더로 변경 → 동기화 상태가 초기화되는지 (기존 리소스 갱신 실패가 반복되지 않아야 함)
  6. 연동 해제 → 자격증명이 지워지되 서버의 일정은 그대로 남는지

2. 다른 빌드/릴리스가 필요한 것

보류 U-4. 자동 업데이트 "새 버전 있음" 경로

왜 못 하나
GitHub 최신 릴리스가 v1.4.1인데 로컬 빌드는 v2.0.1입니다. electron-updater가 비교할 상위 버전이 없어 업데이트 감지 자체가 발생할 수 없습니다. (dev 빌드는 !is.dev 가드로 아예 비활성 — 설정에서 "업데이트 확인 중"에 머무는 건 정상입니다.)
선행 조건
이 경로는 앱 내 다운로드/설치 배선이 먼저입니다. 2026-08-05 수정 전까지 downloadUpdate/installUpdate IPC가 렌더러에서 호출되지 않아, 새 버전이 감지돼도 GitHub 릴리스 페이지를 여는 것 외에는 아무 일도 일어나지 않았습니다.
검증 절차
  1. 2.0.1보다 높은 버전을 GitHub 릴리스로 발행
  2. 패키징 빌드 실행 → 설정에 "새 버전" 안내가 뜨는지
  3. 다운로드 진행률이 표시되는지 → 완료 후 "재시작하여 설치"가 동작하는지
  4. 재시작 후 버전이 올라갔는지

보류 U-5. MAS(App Store) 빌드 분기

왜 못 하나
dev·패키징 빌드 모두 process.mas === false입니다. MAS 전용 코드 경로가 실행되지 않습니다.
분기되는 동작 3가지
① 설정의 버전 섹션이 "App Store를 통해 업데이트됩니다"로 바뀜
② register-global-shortcut이 no-op으로 빠짐 (샌드박스에서 전역 단축키 등록 불가)
③ download-update/install-update IPC가 no-op
검증 절차
npm run mas:build로 만든 빌드에서 위 3가지를 각각 확인. 특히 ②는 Cmd+Shift+A가 앱 외부에서 안 먹는 게 정상이라는 걸 알고 봐야 합니다.

3. 미검증이 아닌 것 — 구분해 둡니다

아래 항목은 "검증 못 함"이 아니라 기능이 앱에 없는 상태였습니다. 혼동하지 않도록 분리합니다.

별건 라이선스 검증

상태
src/shared/license/(crypto · format · public-key)에 서명 검증 코어와 유닛테스트가 있지만 main/renderer 어디에서도 import되지 않습니다. 현재 빌드에 라이선스 게이트가 없습니다.
다음 단계
유료화 구조가 확정되면 배선 → 그때 검증 대상이 됩니다. 지금은 검증할 기능이 존재하지 않습니다.
