내장 런타임 & 로컬 RAG

2026-07-27 · 로컬 AI/프라이버시 로드맵의 [장기] 두 항목 — 착수 전 결정이 필요한 아키텍처 갈림길

나머지 로드맵 항목(원클릭 온보딩·전송 미리보기·네트워크 인디케이터·한국어 모델·기존-할일 액션)은 이번 세션에 모두 구현했습니다. 남은 내장 런타임과 로컬 RAG는 네이티브 모듈 번들링·패키징· 임베딩 저장 스키마 등 되돌리기 어려운 결정이 선행돼야 해, 밤샘 무검증 구현 대신 이 제안서로 정리합니다. 각 항목의 접근·트레이드오프·결정 사항을 아래에 두고, 승인 시 단계적으로 구현합니다.

1 내장 런타임 장기

Ollama 의존을 없애고 앱만 설치하면 로컬 AI가 되도록 — node-llama-cpp(llama.cpp 바인딩)로 GGUF 모델을 앱 프로세스 안에서 직접 구동한다.

  • 설치 0 — 사용자가 Ollama를 따로 깔 필요 없음(온보딩 마찰 제거)
  • 완전 온디바이스 — 이그레스 자체가 불가능(프라이버시 최상)
  • 서버 프로세스/포트 관리 불필요
  • 번들 크기 급증 — 아키텍처별(arm64/x64) 네이티브 바이너리 + GGUF 모델 2–5GB
  • macOS 패키징 난이도 — 네이티브 모듈 코드서명/노터라이즈, MAS 샌드박스는 JIT/네이티브 실행 제약으로 사실상 불가 가능성
  • 런타임 리소스 — RAM/CPU 점유, 콜드 로드, 배터리
  • 유지보수 — 모델·바인딩 버전 추적, 아키텍처 매트릭스 빌드
측면Ollama(현행)내장 런타임(제안)
설치사용자가 Ollama 설치 필요없음(앱에 포함/최초 실행 시 모델 다운로드)
번들수 MB+네이티브 바이너리, 모델은 번들 또는 다운로드(2–5GB)
배포 채널Developer ID · MAS 모두 OKDeveloper ID 위주 — MAS는 검증 필요
프라이버시로컬 루프백(온디바이스)완전 인프로세스(이그레스 불가)

결정 필요

  1. 번들 vs 최초 실행 다운로드 — 앱 크기(2–5GB↑)를 감수할지, 첫 실행에 모델을 받을지
  2. 기본 모델 — 한국어 품질 고려(예: EXAONE 3.5 GGUF). 크기/품질 트레이드오프
  3. 배포 채널 — MAS 샌드박스에서 동작 불가 시, 내장 모드는 Developer ID 빌드 전용으로 한정할지
  4. 아키텍처 — arm64 전용 vs arm64+x64 유니버설(빌드 시간/크기)
  5. 폴백 — Ollama를 계속 1순위로 두고 내장은 옵트인 "내장 모드"로 병행할지

2 로컬 RAG / 임베딩 장기

지금은 buildAiTaskContext가 상위 ~40개 태스크를 통째로 전송한다. 질의와 관련된 태스크만 골라 보내면 이그레스 감소(프라이버시) + 답변 초점 향상을 동시에 얻는다.

v1 — 키워드 관련도(스테핑 스톤, 임베딩 불필요)

  • 순수 함수 · 네트워크 0 · 즉시 테스트 가능 — 질의 토큰과 태스크(제목/태그) 겹침으로 상위 K 선택
  • 추가 모델 설치/스키마 변경 없음 — 지금 바로 구현 가능
  • 의미 검색은 아님 — 동의어/문맥은 못 잡음(“장보기” vs “마트”)

v2 — 임베딩(의미 검색)

Ollama /api/embeddings(예: 한국어에 강한 bge-m3/nomic-embed-text)로 태스크를 임베딩, 콘텐츠 해시로 캐시, 질의 임베딩과 코사인 유사도 상위 K 전송.

  • 임베딩 모델 추가 설치 필요
  • 임베딩 저장/캐시 — DB 테이블·컬럼 추가 + 태스크 편집 시 무효화
  • 콜드스타트(최초 전량 임베딩) 비용

결정 필요

  1. v1(키워드)부터 출시할지 — 저위험·즉시 가치. 이후 v2(임베딩) 승격
  2. 임베딩 모델 선택(한국어 품질) 및 자동 설치 유도 여부
  3. 저장 위치 — 새 DB 테이블 vs 태스크 행 컬럼(BLOB), 무효화 트리거(저장 시 재임베딩 vs 지연)
  4. 상위 K 크기 + 최근성 하한(관련도 낮아도 최근 태스크 N개는 유지할지)
  5. 프라이버시 표기 — 전송 미리보기(이미 구현)와 연동해 "관련 N개만 전송" 노출

➤ 추천 실행 순서

1
로컬 RAG v1(키워드 관련도) 먼저 — 순수·테스트 가능·저위험. 전송 태스크를 질의 관련 상위 K로 축소해 이그레스를 즉시 줄인다. (승인 시 이번 주 구현 가능)
2
로컬 RAG v2(임베딩) — 임베딩 모델·캐시 스키마 결정 후. 의미 검색으로 recall 향상.
3
내장 런타임 — MAS 샌드박스 실증 스파이크 먼저(동작 가능 여부 확인). 가능하면 Developer ID 빌드에 옵트인 "내장 모드"로, Ollama는 1순위 유지.
4
각 단계는 독립 출시 — 하나가 막혀도 나머지는 진행. 내장 런타임은 번들 크기 결정이 가장 큰 게이트.
